# 大幅网点图分条打样系统

基于 **Flask + Pillow + NumPy** 的网页应用：对宽高各至多 2048 像素的 **8 位灰度 PNG**
做 Floyd–Steinberg 误差扩散二值化，支持制版员在预览上框选强制黑/白、按行号登记
已打样条带，并以"续算"方式增量改稿——续算结果与从头重算**逐像素一致**。

成稿页另带**反白细线扩墨预检**：框选 ≤256×256 区域并点两个白点作端点，
试算 0–16 整数扩墨档下的四邻接通道，给出仍有通道的最高档及其一条最短通道，
并在换稿成功后按原框/端点自动重测（过期响应不上屏，改稿被拒则沿用旧结论）。

## 1. 抖动规则（严格实现）

- 扫描顺序：从左到右、从上到下。
- 校正灰度 `corrected = 原灰度 + 累积误差`，中间灰度保持浮点，**不截断**。
- `corrected < 128` 落黑（0），否则落白（255）。
- 误差 `e = corrected − 实际落色值`，按 Floyd–Steinberg 权重扩散：
  右 7/16、左下 3/16、正下 5/16、右下 1/16；**图外误差直接舍弃**。
- 强制色像素输出强制黑/白，但误差仍按其**实际落色**计算并继续扩散，
  所以强制改动会像真实落色一样把影响向后传播。

## 2. 续算与缓存预算

- 每稿缓存 **⌈图高/32⌉ 条全宽误差行**作为检查点（固定在第 0、32、64… 行的入流快照），
  另有 **2 行工作区**处理当前行/下一行，物理上合计 `⌈H/32⌉ + 2` 行（2048 高时为 66 行）。
- 改稿后续算起始行 = `floor32(最早改动行)`，即**最多回到最早改动行之前 31 行**。
- 检查点 pin slot 只存入流快照；处理检查点行时在工作区使用副本，右扩散不污染快照。
- 续算前保留起始检查点的入流（来自未改动的上方行），清空其下误差行后重算到图底，
  因此与同一强制色数组从头重算**逐像素（逐位浮点）一致**。

## 3. 条带与换稿规则

- 可按 1 基行号登记多段已打样条带 `[起始行, 结束行]`。
- 每次框选强制色产生一个候选稿，系统逐条带比对旧稿与候选稿：
  - **条带内存在网点变色** → 拒绝换稿，标出该条带内**首个变色点**（行优先扫描），
    旧稿及其强制色原样保留；可在"被拒候选稿"页签查看全部变色区域（绿）与首个变色点（橙十字）。
  - **所有条带内均无变色** → 接受换稿，候选稿成为当前稿，可下载新的黑白 PNG。

## 4. 反白细线扩墨预检

实现在 `app/preflight.py`，无额外依赖。

- **检查框**：在预检工具下拖出，宽、高各 **≤ 256 像素**；再在框内单击
  **两个不同的当前成稿白点**作为端点（前端会读回 `/image/out` 像素拦掉黑点，
  后端也校验框/端点；换稿后原端点即使变黑也不报错，而判为零档已断）。
- **扩墨模型**：对当前正式成稿（当前 revision 的二值 `out`）计算每个像素到
  **最近黑点的曼哈顿距离** `d`；第 `k` 档（`k = 0..16` 整数像素）下
  `d ≤ k` 的像素视为黑点，其余为白点。距离变换为精确两遍 chamfer（曼哈顿度量）。
- **取数范围**：只读**检查框 + 四周 16 像素**的裁剪区（接口返回实际 `read_region`）。
  框外 16 像素以外的黑点到框内任意像素距离必 >16，不可能影响任何一档。
- **通道搜索**：严格限制在检查框内，只允许**上/下/左/右相邻**的当档白点。
  从 0 档起逐档 BFS；可通行集合随档位单调收缩，首个断档之上即最高连通档，
  该档 BFS 父链重建出**一条最短通道**（边数最少）。
- **结果展示**：侧栏给出 0–16 档连通色块与最高档，画布叠加青色检查框、
  A/B 端点和绿色最短通道；**零档已断**时红色提示并**撤下通道线**。
- **换稿一致性（过期响应保护）**：
  - 换稿**成功**后，若已有完整的"框 + 两端点"，立即撤下旧结论/旧通道线并显示等待，
    随后按**原框和原端点**对新稿自动重测；
  - 响应返回时，只有**会话、当前成稿 revision、框、两端点都与发起时完全一致**
    才上屏（另带请求序号 token 兜底），过期响应直接丢弃；
  - 换稿**被拒**时 revision 不变，页面**沿用当前预检结果与通道线**。

## 5. 启动方式

### Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

Compose 把宿主机 `./data` 挂到容器 `/app/data`；内置样图与预检演示图已打进镜像。

### 本地 Python

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m app.server          # 默认 8000 端口，可用 PORT 环境变量覆盖
```

## 6. 网页演示流程

### 6.1 条带拒绝/接受与续算（内置样图）

点击"载入内置样图"（256×256 灰度，`sample/sample.png`，由 `sample/make_sample.py` 生成）：

1. 登记条带：起始行 `1`、结束行 `64`。
2. 在条带内部框选一小块"强制黑"→ 误差扩散使条带内网点变色，
   系统拒绝换稿并提示首个变色点，旧稿保留。
3. 在条带之外（如第 200 行附近）框选强制色 → 条带内无变色，换稿被接受，
   界面显示续算起点（检查点行号）与改动行。
4. 在"强制色叠加"页签查看蓝（强制黑）/红（强制白）标记；下载当前稿黑白 PNG。

### 6.2 预检 + 改稿后自动重测（推荐用专用线稿图）

点"**载入反白细线预检演示图**"（`sample/preflight_demo.png`，纯黑白 256×256，
由 `sample/make_preflight_demo.py` 生成；载入后自动进入预检交互）。

1. **框选**：在图的上半区，从约 `(24,48)` 拖到 `(235,95)`，框住整条 Z 形白线
   （宽 212、高 48，均 ≤256）。拖红表示超过 256，需重框。
2. **端点**：在上横段中央白点 `A≈(44,59)` 点一下，再在下横段中央白点
   `B≈(214,85)` 点一下（点到黑点会被拦下并提示）。
3. 自动试算后，侧栏显示"**仍有通道的最高扩墨档：1 像素**"，0、1 档为绿、
   2–16 档为红，画布画出第 1 档的一条绿色最短通道。
4. **改稿后重测**：
   1. 点左侧"**⏹ 预检进行中…（点此回到强制色）**"退出预检工具；
   2. 在 Z 线中段的竖直细颈（约 x=117–119、y=74–77）上，拖一个**横向跨过细颈**
      的小"强制黑"框，例如从 `(116,74)` 拖到 `(120,77)`（提交半开框
      `x0=116,y0=74,x1=121,y1=78`；两侧多包黑底无副作用）；
   3. **不登记条带**时换稿必被接受。松开后可看到旧通道线立即撤下、显示
      "正在按新稿重测"，随后新结论出现：细颈被切断，"**零档已断**"，通道线不再画出。
5. 点"强制色"卡片里的 **清除强制色**，在同一切口位置拖一个清除框，稿件恢复，
   预检再次自动重测回"最高档 1"。也可随时点"**用原框和端点重测**"。
6. **零档已断的初始样例**：点"📐 框选预检区域"，框住下半区中间带断口的横线
   （约 `(24,168)`–`(235,191)`），端点取 `(44,179)`、`(214,179)`，
   会直接得到红色"零档已断"提示且没有通道线。
7. **改稿被拒时沿用预检结论**：先登记条带 `60–95` 行，重新做第 4 步的细颈强制黑。
   换稿被拒并跳到"被拒候选稿"页签，但预检卡片仍显示"最高档 1"，
   青色框、A/B 与原绿色通道线都保留在叠加层上。

> 也可以在普通"载入内置样图"或任意上传稿上使用预检：切到"二值成稿"页签，
> 点"框选预检区域"即可。网点图中通道通常只能承受 0–2 档，属正常结果。

## 7. 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/upload` | 上传 8 位灰度 PNG（multipart 字段 `image`） |
| POST | `/api/sample` | 载入内置样图 |
| POST | `/api/preflight-demo` | 载入反白细线预检专用线稿图 |
| GET  | `/api/session/<sid>` | 会话/稿件/条带/缓存预算信息 |
| POST | `/api/session/<sid>/strips` | 登记条带（1 基 `top_line`/`bottom_line`） |
| DELETE | `/api/session/<sid>/strips/<index>` | 删除条带 |
| POST | `/api/session/<sid>/force` | 框选强制色 `{x0,y0,x1,y1,mode}`，mode=black/white/clear |
| POST | `/api/session/<sid>/preflight` | 反白预检 `{x0,y0,x1,y1,endpoints:[[x,y],[x,y]]}`（框半开、宽高≤256），返回 `max_level`/`levels`/`path`/`revision_id`/`read_region` 等 |
| GET  | `/api/session/<sid>/image/{gray,out,force}` | 原图/成稿/强制色叠加 PNG |
| GET  | `/api/session/<sid>/pending/image` | 被拒候选稿变色叠加预览 |
| GET  | `/api/session/<sid>/download` | 下载当前稿黑白 PNG |

`/preflight` 响应要点：`max_level` 为 `null` 表示零档已断（`reason` 为
`broken_at_zero` 或端点变黑的 `endpoint_black`）；`path` 是最高档最短通道的
`[[x,y], ...]`（零档断时为空数组）；`revision_id` 是计算所依据的成稿版本，
供前端做过期响应判定。参数非法返回 HTTP 400 与 `{error}`。
